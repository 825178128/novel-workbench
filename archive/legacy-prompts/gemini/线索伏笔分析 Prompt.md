# 判定无效的触发条件 (Null Trigger)
如果该片段符合以下任意情况，请立刻将 `is_valid` 设为 false：
1. **直白因果/无伪装**：这是正常的按顺序叙事（例如主角买了一瓶药，后来喝了），不存在任何信息隐藏或误导。
2. **机械降神式填坑**：作者强行给主角开挂解决危机，并用生硬的旁白解释“其实这多亏了很久以前的某件事”，但缺乏巧妙的逻辑闭环。
3. 文本中没有任何使得读者产生“恍然大悟(Ah-ha moment)”或“细思极恐”的情绪反转。

# 高质量抽象指南 (Analysis Guidelines)
当你判定该伏笔设计有高提取价值时，请重点剖析以下魔术手法的“作者操作”：
1. **伪装与埋藏 (Camouflage & Planting)**：作者最初是如何掩盖这条线索的？（例如：利用【情绪盲区】，在读者被搞笑桥段吸引时塞入关键道具；利用【信息过载】，将其混在一堆毫无用处的垃圾设定中；伪装成【角色性格缺陷】，让异常行为看似合理）。
2. **认知误导 (Misdirection)**：作者是如何利用读者的思维定势或主角的主观视角（POV限制），引导大家往错误的方向去猜想的？
3. **回收与引爆 (Payoff Mechanism)**：伏笔揭晓时，是如何与当前的危机或爽点完美咬合的？创造了怎样的情绪冲击（如：绝处逢生、毛骨悚然、命运闭环）？

# 核心输出要求 (Output Constraints)
- 必须严格遵循全局设定的纯 JSON 格式输出。
- `analysis_target_type` 必须固定为 "hook"。
- 在 `core_mechanism.operation_name` 中，提取具体的伏笔模型（例如：“盲区植入法”、“双重反转误导模型”、“麦高芬伪装术”）。
- 在撰写 `transferable_technique`（跨题材复用指南）时，绝对禁止使用原著线索的具体名称（如：羊皮卷、神秘老爷爷），必须替换为（看似无害的日常物件、看似合理的环境噪音、被故意扭曲的前置信息）。**步骤必须具有“魔术教学”般的可操作性**。
- `evidence` 必须是输入文本中的精确子串，且重点提取作者“揭晓真相那一刻”的描述，或者回忆杀中揭示“伪装”的句子。
