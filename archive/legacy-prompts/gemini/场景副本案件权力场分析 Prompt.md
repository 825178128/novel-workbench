# 判定无效的触发条件 (Null Trigger)
如果该片段符合以下任意情况，请立刻将 `is_valid` 设为 false：
1. **纯背景板**：场景只是角色对话或战斗的物理背景，没有任何特殊规则、环境压力或隐性限制（如：只是在普通的客栈里打了一架）。
2. **设定流水账**：只是单向宣读副本有什么怪、掉落什么宝物，没有展现角色与这些设定的交互或利用。
3. 没有任何“资源稀缺性”或“多方势力冲突”，仅仅是单一的线性通关。

# 高质量抽象指南 (Analysis Guidelines)
当你判定该容器设计有高提取价值时，请重点剖析以下三个维度的“作者操作”：
1. **压力系统与规则限制 (Pressure & Rule Design)**：作者引入了什么外部压力机制迫使角色必须立刻行动？（例如：倒计时死亡线、不断缩小的安全区、严苛的规则惩罚、环境天然的Debuff）。
2. **规则剥削与破局点 (Rule Exploitation)**：在作者设定的这个牢笼里，主角是如何“卡Bug”、利用规则漏洞或信息差来形成降维打击/爽点的？
3. **势力制衡与博弈 (Faction Dynamics)**：如果存在第三方或多方势力，作者是如何设计利益分配，使得各方形成互相牵制（如：三国杀结构、黑暗森林法则），从而避免故事变成无脑的单挑？

# 核心输出要求 (Output Constraints)
- 必须严格遵循全局设定的纯 JSON 格式输出。
- `analysis_target_type` 必须固定为 "container"。
- 在 `core_mechanism.operation_name` 中，提取具体的场景设计模型（例如：“囚徒困境式副本模型”、“倒计时高压釜模型”、“资源零和博弈场”）。
