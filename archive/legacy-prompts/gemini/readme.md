# 🖋️ Web Novel Workbench (网文工作台 - 创作技法逆向拆解系统)

## 🌟 项目简介
“网文工作台”不是一个用于生成剧情梗概、角色百科或总结摘要的阅读器。它是一把**面向创作者的“手术刀”**。
本系统的核心目标是从海量成熟网文中，反向剥离出底层叙事骨架、信息控制策略与情绪操纵规律，最终沉淀为创作者可直接“抄作业”的**可复用创作技法卡**。

我们不关心“谁杀了谁”，我们只关心“作者是如何通过隐瞒这把刀的存在，制造出极致的悬念与爽点”。

---

## 🎯 核心设计理念 (Core Philosophy)

本系统的所有 LLM 交互均基于以下四大铁律设计：
1. **作者视角，非读者视角**：所有产出必须是以“作者通过（操作）实现了（目的）”为基本范式的分析，彻底杜绝流水账式的剧情总结。
2. **严防幻觉，物理锁死**：无证据不立论。分析产出必须附带 `evidence`，且所有证据必须 100% 对应原文原句（精确子串匹配）。
3. **强复用导向 (Actionable)**：分析结论必须能转化为通用方法论，剔除所有原著专有名词，抽象为“信息差”、“资源分配”、“生态位”等通用概念。
4. **宁缺毋滥 (Null Trigger)**：接受极低的有效产出率。如果一段文字只是过渡水文，AI 会果断拦截并返回空，绝不为了填满字段而编造废话。

## 🧠 核心 Prompt 矩阵 (Prompt Matrix)

系统内置 8 套经过深度抗幻觉与防偏离测试的高质量 Prompt，构成完整的逆向工程管线：

| 编号 | 模块名称 | 职责定位 | 输入特征 |
| :--- | :--- | :--- | :--- |
| **P1** | 全局基座 System Prompt | 确立“逆向工程师”角色，定义纯 JSON 强类型输出、CoT 思维链隔离以及反剧情总结法则。 | 全局共享 |
| **P2** | 剧情单元分析 | 拆解“起承转合”、冲突构建机制、期待感建立与爽点爆发模型。 | 文本切片 + 候选主题 |
| **P3** | 人物塑造分析 | 剥离设定表象，拆解角色的“叙事生态位”、侧面烘托微操与关系张力。 | 文本切片 + 候选角色 |
| **P4** | 场景/权力场分析 | 拆解特殊规则容器、倒计时压力系统、规则剥削以及多方势力纳什均衡博弈。 | 文本切片 + 候选场景 |
| **P5** | 线索/伏笔分析 | 采用“魔术师视角”，拆解草蛇灰线的伪装术、信息转移与认知误导机制。 | 文本切片 + 候选线索 |
| **P6** | 节奏控制分析 | 弃用“快慢”伪概念，通过“信息滴漏法则”和“章末钩子(Hook)”类型学拆解断章艺术。 | 跨章末高压切片 |
| **P7** | 创作技法抽象 | 融合中转站。将 P2-P6 的零散结论高度抽象为无专有名词、强执行步骤的“原子技法卡”。 | P2-P6 的结果集合 |
| **P8** | 质量审核 (QA) | 魔鬼质检员。利用反向 KPI 拦截剧情复述和正确的废话，低于 4 分的技法直接丢弃。 | P7 技法卡 + 原文 |

## 🏗️ 核心工作流 (Execution Pipeline)

建议按照以下工业化流水线串联 Prompt 与后端代码：

1. **Local Filtering (本地低成本预检)**：
   使用低配大模型（如 DeepSeek V4-Flash）或 NLP 实体识别，粗筛出包含剧烈冲突、多方对话、章末悬念的“高优文本切片”，过滤日常水文。
2. **Parallel Dispatch (多路并发拆解)**：
   将切片结合 **P1(系统设定)**，并发派发给 **P2-P6(维度提取)** 进行深度结构化提炼。
3. **Abstraction (原子化提纯)**：
   收集阶段二的有效 JSON 结果，使用最高智商模型（推荐 Claude 3.5 Sonnet / GPT-4o），调用 **P7** 提纯出“技法卡”。
4. **QA & Persistence (魔鬼质检与入库)**：
   将技法卡送入 **P8** 进行逻辑验证。**同时，后端触发物理防线验证（见下文）**，双端通过后方可持久化入库。

## 🛠️ 工程落地防线 (Engineering Safeguards)

**⚠️ 警告：绝对不要 100% 信任大模型的 JSON 输出。系统后端必须具备以下防线：**

### 1. JSON 强力清洗层
- LLM 偶尔会输出 Markdown 代码块（如 ````json ... 
````）或附加闲聊。
- **对策**：封装一个 `clean_json_string(raw_res)` 函数，使用正则剥离所有非 JSON 字符。若 `JSON.parse` 依旧失败，切勿尝试代码自动修复，直接判定本次调度失败并进入重试队列。

### 2. Evidence 物理级校验 (重中之重)
- LLM 极易为迎合自己的结论伪造原文证据。
- **对策**：在取得最终分析结果前，系统底层必须执行物理校验：

// 伪代码示例
const isValid = technique_card.evidence.every(str => 
    original_text.includes(str)
);
if (!isValid) throw new Error("幻觉拦截：Evidence非精确子串");
