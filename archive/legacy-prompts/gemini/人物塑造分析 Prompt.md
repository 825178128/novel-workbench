# 判定无效的触发条件 (Null Trigger)
如果该角色或片段符合以下任意情况，请立刻将 `is_valid` 设为 false：
1. **工具人/背景板**：该角色在此片段中仅为推动剧情、传递基础信息或提供背景音（如：路人甲、报信的小兵、无明显交互的服务人员）。
2. **纯设定宣告**：作者只是干巴巴地用旁白罗列该角色的外貌、身世和性格，并没有通过具体的“事件、动作或对话（Show, Don't tell）”来展现。
3. 没有体现出该角色独特的“叙事功能”或与主角的“关系张力”。

# 高质量抽象指南 (Analysis Guidelines)
当你判定该人物塑造有高提取价值时，请重点剖析以下三个维度：
1. **叙事功能 (Narrative Function)**：抛开具体剧情，这个角色在此处的结构作用是什么？（例如：主角当前战力的完美垫脚石 / 读者情绪的缓冲带 / 某个势力规则的具象化代表 / 提供某种特定情绪价值如“反差萌”或“极致压迫”）。
2. **侧面微操 (Show, Don't Tell)**：作者是如何*不直接说明*，而是通过某个细节（如特定的小动作、别人的恐惧反应、极端的环境对比）来凸显其特质的？
3. **关系张力 (Relational Tension)**：作者如何利用该角色与其他角色（尤其是主角）的交互，制造了某种拉扯感、对立感或同盟感？

# 核心输出要求 (Output Constraints)
- 必须严格遵循全局设定的纯 JSON 格式输出。
- `analysis_target_type` 必须固定为 "character"。
- 在 `core_mechanism.operation_name` 中，请提取出具体的塑造模型（例如：“高位者降维威慑模型”、“侧面烘托式出场法”、“缺点反衬法”）。
- 在撰写 `transferable_technique`（跨题材复用指南）时，绝对禁止使用输入文本中的人名。必须转化为通用指导（例如：“步骤1：通过周围低阶角色的本能恐惧反应，来烘托该高位角色的压迫感，而非直接描写其武力值”）。
- `evidence` 必须是输入文本中的精确子串，且必须包含能体现上述“微操”的原句。
