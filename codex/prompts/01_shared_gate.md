# 共享六问门禁

所有模块在输出前，必须进行内部自检。不要输出自检过程，只输出最终 JSON。

## 1. 如何防止写成剧情总结？

自问：

- 这条内容是否只是复述“发生了什么”？
- 是否明确写出了“作者用了什么创作操作”？
- 是否说明该操作制造了什么阅读效果？
- 是否说明这个写法如何被创作者迁移？

处理规则：

- 如果只能写剧情，不能写创作操作，删除该条。
- 如果 `surface_summary` 比 `author_operation` 更重要或更长，压缩剧情摘要，强化创作操作。
- 如果没有 `reader_effect` 和 `reuse_method`，该条不合格。

## 2. 如何防止 AI 编造？

自问：

- 每个核心结论是否有原文证据？
- 是否把本地候选当成了事实？
- 是否推断了文本中没有出现的人物动机、作者意图或后续回收？
- 是否把“可能”写成了“确定”？

处理规则：

- 没有证据的结论必须删除。
- `evidence.quote` 必须是输入原文中的精确子串，不能改写，不能把概括当证据。
- 证据弱但仍有观察价值，可以降低 `confidence`，并在 `risk_flags` 标注 `weak_evidence`。
- 没有后文证据时，不得断言“伏笔已回收”，只能写 `suspected`。
- 低于输出阈值的候选不要输出。

## 3. 如何判断候选是否值得入库？

自问：

- 这条分析是否能沉淀成技法、结构、模板或风险提醒？
- 是否足够具体，区别于“设置悬念”“制造冲突”“塑造人物”这类空泛说法？
- 是否有明确原文证据、作者操作、读者效果和复用方法？
- 是否值得创作者以后检索和复用？

处理规则：

- 使用 `storage_decision` 明确是否建议入库。
- `should_store=true` 的最低条件：
  - 有明确原文证据。
  - 有作者操作分析。
  - 有读者效果说明。
  - 有创作者复用方法。
  - `confidence >= 0.65`。
  - `value_score >= 0.60`。
- 不满足最低条件时，`should_store=false`。

## 4. 如何转成创作者可复用的方法？

自问：

- 是否从具体文本抽出了可迁移结构？
- 是否告诉创作者可以在哪些题材或场景中使用？
- 是否给出落地步骤、模板或变体？
- 是否提醒复用时容易写坏的地方？
- 复用字段中是否已经剥离原文专有名词？
- 方法是否能通过跨题材测试：换成都市、悬疑、科幻、言情等题材后仍然成立？

处理规则：

- `reuse_method` 不能只写“可用于制造悬念”。
- 应写成“当你要制造 X 效果时，先做 A，再做 B，最后保留 C”。
- `reuse_method`、`migration_method`、`execution_formula`、`example_rewrite_prompt` 中不得出现原文角色名、地名、势力名、功法名、道具名、案件名。
- 把专有名词替换成：主角方、高位者、信息劣势方、资源垄断者、第三方变量、核心诱饵、隐性规则、触发物。
- 优先使用操作级动词：隐藏、切断、暴露、延迟、转移、错置、剥夺、抬高、压缩、反转、回收。
- 有条件时提供 `failure_modes`，说明滥用风险。

## 5. JSON schema 是否适合程序稳定解析？

自问：

- 是否是合法 JSON？
- 字段名是否稳定？
- 同类字段的类型是否稳定？
- 空值是否按约定输出？
- `confidence` 是否是 0 到 1 的数字？

处理规则：

- 只输出 JSON，不输出 Markdown。
- 不输出注释。
- 不使用动态字段名。
- 空列表用 `[]`。
- 不适用或未知用 `null`。
- 文本字段没有内容时用空字符串 `""`，不要省略必填字段。

## 6. 不同模块之间字段是否统一？

所有模块的 `items[]` 必须包含以下基础字段：

- `id`
- `type`
- `name`
- `surface_summary`
- `author_operation`
- `reader_effect`
- `evidence`
- `reuse_method`
- `failure_modes`
- `storage_decision`
- `confidence`

模块可以增加专属字段，但不得改变基础字段含义。

## 7. 是否通过动作级技法测试？

自问：

- 这条方法是否能被改写成“动作 + 信息差/资源/认知/关系变化”的结构？
- 新手作者看完后，是否知道下一段该怎么写，而不是只知道“要更精彩”？
- 技法是否能脱离当前题材和设定成立？

处理规则：

- 如果只能得到“制造冲突”“增加压迫感”“塑造人物反差”这类空泛结论，删除该条或降为无效。
- 如果能改写为“向读者暴露主角不知道的危险”“切断角色获取关键资源的路径”“用第三方变量打破原有博弈平衡”，才具备入库价值。
